# TropoSense – Smart Healthcare Platform v2

ต้นแบบเว็บแอป 6 โมดูล ต่อจากโปรเจกต์เดิม ใช้ React 19 + TypeScript + Vite + Lucide Icons ไม่มี Backend ไม่ต้องใช้ API Key ใช้ข้อมูลสมมติเท่านั้น

## เปิดเว็บไซต์

ติดตั้ง Node.js 24 LTS (หรือ Node.js 22.12 ขึ้นไป) เปิด Terminal ในโฟลเดอร์นี้:

```sh
npm ci
npm run dev
```

เปิด Local URL ที่ Vite แสดง เช่น http://127.0.0.1:5173 กดทดลองใช้งานแพลตฟอร์ม และเลือก Demo Role

บน Windows ดับเบิลคลิก `Start-TropoSense.cmd` ได้ สคริปต์จะติดตั้ง dependencies ถ้ายังไม่มี แล้วเริ่ม server ให้เปิด URL ที่แสดงด้วยตนเอง

```sh
npm test
npm run build
npm run preview
```

Production Build อยู่ใน `dist/` สำหรับ Static Hosting การนำทางใช้ URL hash ไม่ต้องมี route fallback อย่าเปิด index.html ด้วย file:// ให้ใช้ dev/preview server

## Demo Roles

- Administrator: จัดการทุกแฟ้ม QC คำตอบแพทย์สมมติ ตั้งค่า ลบแฟ้ม และรีเซ็ตข้อมูล
- Healthcare Professional: ดู เพิ่ม แก้ไขแฟ้ม QC และข้อมูลการดูแลได้ แต่ตั้งค่าส่วนกลางและลบแฟ้มผู้ป่วยไม่ได้
- Patient: เห็นเฉพาะ PT-0001 กับรายการของแฟ้มนี้ บันทึกอาการ ค่าตรวจ นัดหมาย และสร้างคำขอปรึกษาของตนเอง เข้า QC และแก้ Doctor Notes ไม่ได้

กดบัญชีมุมขวาบนเพื่อสลับบทบาท ไม่มีรหัสผ่านหรือการยืนยันตัวตนจริง สิทธิ์ตรวจทั้ง UI และฟังก์ชันเปลี่ยนข้อมูล แต่เป็น Frontend Demo ไม่ใช่ security boundary สำหรับข้อมูลผู้ป่วยจริง

PT-0001 สงวนไว้สำหรับ Patient Demo จึงลบผ่าน UI ไม่ได้ การลบแฟ้มอื่นจะลบประวัติที่ผูกกับแฟ้มนั้นด้วย

## การจัดเก็บข้อมูล

- ใช้ LocalStorage key `troposense-demo-v2`, schema version 2 ข้อมูลคงอยู่หลังรีเฟรช บทบาทเก็บใน SessionStorage ของแต่ละแท็บ
- ใช้ข้อมูลสมมติเท่านั้น ห้ามกรอกชื่อ เบอร์โทร ข้อมูลสุขภาพ หรือตำแหน่งของบุคคลจริง LocalStorage ไม่เหมาะกับข้อมูลสุขภาพจริง
- รับการเปลี่ยนข้อมูลจากแท็บอื่นผ่าน storage event และอ่านข้อมูลล่าสุดก่อนบันทึก การแก้รายการเดียวกันพร้อมกันยังเป็น last-write-wins ไม่ใช่ระบบธุรกรรมหลายผู้ใช้
- หาก LocalStorage ใช้ไม่ได้ จะแจ้งเตือนและเก็บในหน่วยความจำชั่วคราว ข้อมูลรูปแบบผิดจะใช้ชุดตัวอย่างโดยยังไม่เขียนทับจนกว่าจะบันทึกใหม่
- ภาพอัปโหลดอยู่ในหน่วยความจำ ไม่ถูกส่งออกและไม่เก็บใน LocalStorage
- Settings → คืนข้อมูลตัวอย่างเริ่มต้น จะแทนที่ข้อมูลทุกโมดูล ส่งออก JSON ก่อนเพื่อเก็บสำเนาได้ ยังไม่มี UI นำเข้า JSON
- `localhost:5173` กับ `127.0.0.1:5173` เป็นคนละ origin จึงมีพื้นที่ข้อมูลแยกกัน

## ข้อจำกัดทางการแพทย์

> TropoSense เป็นโครงการนวัตกรรมต้นแบบเพื่อการพัฒนาและสาธิตแนวคิด ระบบยังอยู่ระหว่างการทดสอบความเข้ากันได้และประสิทธิภาพ ไม่ใช่อุปกรณ์ที่ผ่านการยืนยันความแม่นยำทางคลินิก และไม่สามารถใช้แทนการวินิจฉัยหรือการรักษาโดยแพทย์ได้

- Accu-Chek Guide ยังไม่ได้รับการยืนยันความเข้ากันได้กับปฏิกิริยาของ TropoSense
- OCR จำลองให้ 124 mg/dL สำหรับทุกภาพ ไม่ได้อ่านข้อความจากภาพจริง
- Glucose ไม่ใช่ cTnI โดยตรง รุ่นนี้เตรียม Logarithmic Calibration แต่ค่าใช้งานจริงยังว่าง จึงไม่แสดง cTnI จนกว่าจะมี Calibration ที่ผ่านการตรวจสอบ หรือผู้ใช้เลือก DEMO อย่างชัดเจน
- cTnI เดิมที่บันทึกแยกยังคงเป็นประวัติจำลอง ส่วนรายการใหม่ใช้ Calibration ร่วมกันทุกเส้นทาง มีคำเตือน DEMO และไม่มีเกณฑ์ปกติ/ผิดปกติ
- TropoBot ไม่มี AI Model ทางการแพทย์ Low/Moderate/High Risk เป็นป้ายสถานการณ์สมมติ ไม่ใช่ระดับความเสี่ยงทางคลินิก Low Demo ไม่ได้ยืนยันว่าปลอดภัย
- กติกาสาธิต: เจ็บ/แน่นหน้าอกหรือหายใจลำบาก → High Demo; อาการอื่น → Moderate Demo; ไม่เลือกอาการ → Low Demo พร้อมคำเตือนไม่ยืนยันความปลอดภัย
- หากมีอาการเจ็บหรือแน่นหน้าอก หายใจลำบาก หรืออาการฉุกเฉินจริง ให้ติดต่อ 1669 หรือเข้ารับการรักษาทันที ไม่ต้องรอเว็บไซต์
- [คู่มือประชาชนในการช่วยเหลือผู้ป่วยฉุกเฉิน](https://www.maelanoihospital.go.th/webhos/wp-content/download/manual/ER.pdf) เป็นแหล่งประกอบข้อมูล 1669 ไม่ได้ใช้เป็นเกณฑ์คำนวณความเสี่ยง
- Emergency, Doctor Connect และ Reminder เป็น Simulation ไม่มีการโทร อีเมล SMS GPS หรือแจ้ง 1669 จริง
- ไม่มีการเชื่อมต่อฐานข้อมูลผู้ป่วยของภาครัฐ

## Break-even Calculator

เงินลงทุน 150,000 บาทเป็นสมมติฐาน ราคาต่อการตรวจ 350 บาทเป็นราคาเป้าหมาย ต้นทุนยังไม่ยืนยันจึงเว้นว่างให้ผู้ใช้กรอกเอง

```text
ส่วนเกินต่อครั้ง = ราคาต่อการตรวจ − ต้นทุนผันแปรต่อครั้ง
ส่วนเกินจากเครื่อง = จำนวนเครื่อง × (4,500 − ต้นทุนต่อเครื่อง)
จำนวนครั้งคุ้มทุน = ceil(max(0, เงินลงทุน − ส่วนเกินจากเครื่อง) / ส่วนเกินต่อครั้ง)
```

ไม่คำนวณเมื่อข้อมูลไม่ครบ ติดลบ จำนวนเครื่องไม่เป็นจำนวนเต็ม หรือส่วนเกินต่อครั้งไม่เป็นบวก ไม่รวมภาษี ดอกเบี้ย และค่าใช้จ่ายอื่นที่ไม่ได้ระบุ

ตัวอย่างทดสอบ: ลงทุน 150,000 / ราคา 350 / ต้นทุน 150 / เครื่อง 0 → 750 ครั้ง; ขายเครื่อง 2 เครื่อง ต้นทุนเครื่องละ 2,500 → 730 ครั้ง

## การสอบเทียบ cTnI

อ่าน `CALIBRATION-AUDIT-TH.txt` สำหรับรายงานตรวจโค้ดและวิธีเตรียมค่าจากการทดลองจริง

ค่าจริงอยู่ใน `src/config/calibration.ts` (เริ่มต้น a,b,C0 เป็น null) สูตรอยู่ใน `src/calibration/evaluate.ts` ทั้ง OCR จำลองและ Manual Input ผ่าน `createRecord()` เดียวกัน ต้องยืนยันตัวเลข/หน่วย mg/dL ก่อนบันทึก และต้องเลือก DEMO เองเมื่อต้องการลองค่าจำลอง

DEMO ใช้ a=50, b=100, C0=1 ng/L เพื่อทดสอบเลขคณิตเท่านั้น ไม่ใช่ผลทดลองหรือค่าจากงานวิจัย ช่วง 50–200 mg/dL เป็นช่วงตัวอย่างทางคณิตศาสตร์ ไม่ใช่ช่วงเครื่องอ่านที่ยืนยันแล้ว ค่า DEMO แสดงคำเตือนตรงตัวทุกตำแหน่ง ไม่ใช้ตัดสินความเสี่ยง

เกณฑ์อ้างอิง cTnI ยังไม่มี (`upperLimitNgL=null`) การสอบเทียบและเกณฑ์ทางคลินิกเป็นคนละ Configuration ต้องมีการตรวจสอบของตนเอง
